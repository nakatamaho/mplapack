# Resident CUDA solvers (factorization goal 08)

The dd, td, qd and MPFR CUDA flavors provide the real and complex
`getrs`, `potrs`, `gesv` and `posv` entry points. For example:

```cpp
#include <mpblas_dd_cuda.h>
bool computed = Rgesv_dd_cuda(n, nrhs, a, lda, ipiv, b, ldb, info);
```

Link `libmplapack_<backend>_opt_cuda`. Headers are generated by
`misc/gen_accelerator_headers.py`. There are eight added public bool symbols
per backend; the ordinary LAPACK names are dispatchers in that same library.

## Contract and arithmetic

* Arguments have exactly the LAPACK order/types. `true` means the device
  computed the result, including a positive numerical `info`. `false` means
  no publication: A, B, pivots, info, unused triangles and padding retain
  their input values. Invalid flags/sizes/pivots, zero n/nrhs, ineligibility,
  allocation failures and device/runtime errors return false. The bool API
  never falls back to the CPU.
* `getrs` uploads LU factors, pivots and B, then runs swaps/TRSM in reference
  order. N, T and C are supported. `potrs` uses the selected U/L triangle
  and the reference pair of triangular solves (conjugating for complex).
  Standalone solves download **B only**; factors and pivots are unchanged.
* Drivers use the existing resident LU/Cholesky engines. Solve follows the
  factorization **before any factor download**. A, pivots and B are published
  once, after all computation/transfers succeed. A singular LU or failed
  Cholesky publishes the reference partial factors/pivots/info but leaves B
  untouched. Cholesky never publishes the opposite triangle.
* Default arithmetic retains reference operation order, recursion, iMlaenv,
  pivots, correctly rounded division, and signed zeros. No reduction/FMA or
  precision policy is relaxed. Fast switches currently retain this schedule.
* BF uses the unchanged resident factor engines. MPFR's optional continuation
  extends their local shape with defaulted nrhs/factorize/trans fields;
  nrhs=0 is the unchanged factor-only path. Real whole-system TRSM uses the
  existing signed/checked inline BLAS update policy; panel arithmetic is
  unchanged. Complex solve arithmetic is the existing signed factor policy.

### The CPU fallback is actually CPU-only

A dispatcher calls its bool entry and, on false, runs the reference routine
text bound to CPU BLAS (`*_omp`, then the native reference). Driver fallbacks
also bind their private reference factors to CPU BLAS. Real GEMM predates
the common bool adapters (`Rgemm_omp`/`Rgemm_reference_cpu` do not exist).
Its legacy `Rgemm_ref` skips zero B entries, unlike the current reference;
that changes signed zeros. The fallback therefore includes the **current
reference GEMM text** under a private name. It neither uses that legacy
zero shortcut nor introduces a CPU-only blocked GEMM dependency.

This matters for MPFR: the legacy fixed complex CUDA BLAS normalizes computed
zeros. A public Cgetrs(C) probe at 512 bits/n=256 lost **256 negative zeros**
when the rejected solver accidentally re-entered that BLAS path. The new CPU
binding avoids that path. Existing **public factor** implementations,
thresholds, arithmetic and schedules are not changed by these private copies.

## Eligibility and controls

Here `<P>` is `MPLAPACK_DD`, `MPLAPACK_TD`, `MPLAPACK_QD` or `MPLAPACK_MPFR`.
Environment controls are read on every call.

| Variable | Meaning |
|---|---|
| `<P>_LAPACK_CUDA=0` | disable resident LAPACK entry points |
| `<P>_LAPACK_CUDA_MIN=N` | common n override, also honored by factor entries |
| `<P>_LAPACK_DRIVER_CUDA_MIN=N` | gesv/posv n override, takes precedence |
| `<P>_LAPACK_SOLVE_CUDA_MIN=N` | getrs/potrs n override, takes precedence |
| `<P>_LAPACK_SOLVE_CUDA_MIN_RHS=N` | standalone minimum nrhs (independent of n) |
| `<P>_LAPACK_FAST=1` | opt-in fast policy; currently the same solver arithmetic |
| `<P>_CUDA_VERBOSE=1` | successful entry's upload / factor_solve / download intervals |

Negative/invalid minimum overrides retain the applicable default. Defaults:

| Backend | gesv real/complex n | posv real/complex n | standalone n / nrhs |
|---|---:|---:|---|
| dd | 2048 / 2048 | 4096 / 4096 | opt-in / 0 |
| td | 1024 / 1024 | 2048 / 2048 | opt-in / 0 |
| qd | 1024 / 1024 | 2048 / 4096 | opt-in / 0 |
| mpfr | 512 / 1024 | 2048 / 2048 | 2048 / 2048 |

BF standalone solves showed no profitable measured CPU/old-GPU crossover;
there is no invented default crossover beyond the measurements. They require
an explicit common or solve-specific n minimum. MPFR standalone 512-point
narrow-RHS calls lose badly to CPU; the measured full-RHS 2048-point calls
beat CPU, though not every one beats the legacy GPU BLAS. These are
conservative policies, **not universal speedup claims**. Driver gates retain
the corresponding factor gates, supported by the measurements below; some
near-break-even complex points and narrow RHS still lose to pure CPU.
The qd complex Cholesky 4096 gate is inherited from the factor measurements,
not a newly measured 4096-point solver crossover. Other MPFR precisions share
this conservative gate; their performance crossover is unmeasured.

To force all eligible small cases in numerical tests, set all three n
minimums **and** `<P>_LAPACK_SOLVE_CUDA_MIN_RHS=0`. The benchmark runner does
this automatically. CPU fallback remains available even without a device.

### MPFR precision, stack and memory

`MPLAPACK_MPFR_CUDA=0` also disables its entries. Eligibility follows the
factor engines: nearest rounding, matching default real/MPC component
precision, finite values, and the supported exponent range. The **whole A**
must satisfy those conditions, including an unused Cholesky triangle;
padding is never inspected. All referenced B values are checked as well.

Automatic 256/512/768/1024/2048-bit calls use fixed arithmetic; other supported
precisions use runtime limbs. `MPLAPACK_MPFR_CUDA_FORCE_RUNTIME=1` forces that
path; `MPLAPACK_MPFR_CUDA_RUNTIME=0` rejects it. Complex eligibility retains
the factor engine's 4096-bit ceiling. GPU arena/precision state is protected
by its existing mutex and restored before publication.

The precision-dependent stack budgets are the unchanged goal-07b policy:

| Engine | Precision / requested KiB |
|---|---|
| real fixed | <=512: 4; <=1024: 8; otherwise: 16 |
| complex fixed | <=1024: 8; otherwise: 16 |
| real runtime | <=1024: 8; <=4096: 16; otherwise: 64 |
| complex runtime | <=1024: 8; <=2048: 16; otherwise: 64 |

Calls only raise the inherited limit, restore it before publication, and
preserve a larger inherited limit. Memory preflight
includes **the full effective stack reservation**, module allowance, arenas,
workspace, pivots, and A+B—not a reduced estimate to make a call eligible.
Restoration failures reject publication. Conversion/publication staging is
transactional even after device computation has completed.

### Default/nonblocking stream dependencies

Pageable H2D copies may return after staging but before DMA has finished.
A nonblocking factor/solve stream must not read them merely because
`cudaMemcpy` returned. Explicit default-stream waits cover matrix/pivot
uploads, BF context constants, and BF real TRSM scalars. In particular MPFR
standalone getrs waits again after its later pivot upload.

`Rsolver_copy_delay.cpp` interposes delayed copies in Linux-only CTest
fixtures: MPFR pivots at 512/200 bits and BF {1,-1} context constants. Positive
cases require the production wait; expected-failing controls skip it and
must expose wrong results. `RUN_SERIAL` keeps these timing-sensitive negative
controls isolated from other tests in one CTest invocation.

## Measurements

A100 80 GB PCIe (driver 580.178.04), CUDA 13.1.115, GCC 15.2.0,
Threadripper 3970X (32 cores / 64 logical CPUs), 32 CPU threads, MPFR 512
bits. Each point is the median of three
fresh-process rounds, interleaving CPU / historical per-call GPU BLAS /
resident entry, reversing the order on alternate rounds. No correctness
GPU jobs ran during these measurements.

All **180 solver medians** (1620 retained samples), including narrow nrhs=1/32,
are in [solvers.csv](../../../benchmark/results/factorization-goal08/solvers.csv).
Drivers cover real/complex gesv/posv, all four backends, n=512/1024/2048,
nrhs=1/n; dd also covers 4096. Standalone solves cover 512 with nrhs=1/32/n,
2048 with nrhs=n, and BF 2048 with nrhs=1.

MPFR real driver entries were remeasured after the inline TRSM policy.
Complex generated fixed/runtime instruction streams were unchanged. Timings
include cold initialization, not just warmed kernels. Split intervals are
wall-clock intervals (packing/staging/publication included; scheduler setup
where applicable), not pure kernel timings, and need not sum to total time.

The historical baseline is explicitly `--legacy` plus
`<P>_LAPACK_CUDA=0`: reference outer solvers calling CUDA BLAS per call.
It is **not** the new CPU-only dispatcher fallback. `Rsolver_legacy_bench.h`
preserves that comparator without weakening production fallback semantics.
Matrices/RHS use deterministic 16-bit dyadic random values; standalone factors
are synthetic nonsingular triangular factors, not preceded by a factorization.

The unchanged MPFR factor path was separately compared with the goal-07b
shared library, full-precision random inputs, three interleaved rounds:
[12 factor medians / 72 samples](../../../benchmark/results/factorization-goal08/mpfr-factor-regression.csv).
New/baseline total ratios are 0.9968–1.0577; factor-interval ratios differ by
at most 1.83%. No factor arithmetic or signed-zero policy changed.

Reproduce, for example:

```sh
python3 benchmark/run_solver_bench.py --bin-dir build/benchmark \
  --backends dd td qd mpfr --rounds 3 --sizes 512 1024 2048 \
  --threads 32 --output drivers.jsonl
python3 benchmark/run_solver_bench.py --bin-dir build/benchmark \
  --routines getrs potrs --sizes 512 2048 --rhs 1 32 0 \
  --rounds 3 --threads 32 --output solves.jsonl
```

## Verification

The new solver/fallback comparisons are strict, not tolerance-based (including
zero signs, A/B padding, unused triangles, pivots and info). Existing
factor/BLAS regressions retain their original criteria (including fast-mode
tolerances and the documented legacy complex-BLAS zero convention); none
was relaxed. Numerical direct-entry
coverage uses n=1/2/3/63/64/65/131/257/599; nrhs=1/n (square RHS through 131),
N/T/C and U/L, ties/swaps, singular/nonpositive factors, zeros and safe-minimum
cases. n/nrhs=0, invalid dimensions/flags/pivots, disabled/threshold/range/
precision rejection and no-publication contracts are also checked.

| Final gate | Result |
|---|---|
| BF CMake direct engines | **PASS 6/6**, 15,683,910 component comparisons each; 0 bit/zero-sign errors |
| MPFR CMake direct engines | **PASS 24/24**: host/device x automatic/runtime x 256/512/768/1024/2048/200 bits; 15,684,422 comparisons each; 0 bit/zero-sign errors |
| Public CPU fallbacks | **PASS 9/9**, 32 cases / 3,219,984 comparisons each, all eight routines, n=257/rhs=1/3; 0 bit/zero-sign errors |
| Delayed-copy publication fixtures | **PASS 10/10** (five positive/five expected-failing controls); BF skipped waits expose 6 wrong results each, MPFR skipped waits expose 2 B mismatches per R/C call |
| Autotools `make check` | **PASS** BF 1/1 each, MPFR 3/3 including the six-precision host sweep |
| No visible GPU | **PASS 8/8** quick host-emulation runs (CMake/autotools x four backends) |
| Final memcheck | **PASS 12/12 required + 2/2 optional 4096-bit runs**, automatic/runtime, 96 direct-entry frame paths / 1056 checks each; 0 sanitizer errors |
| MPFR failure/state contracts | **PASS** low-memory 17, inherited 64-KiB stack 83, injected precision-restoration failure 4 x 7 checks; no publication and successful retry |
| BF factor/BLAS regressions | **PASS 52/52** (the combined CMake run is 61/61 including direct/fallback tests) |
| MPFR factor/BLAS regressions | **PASS 30/30**: 26 completed tests plus four independent full GPU factor sweeps; redundant queued tails were cancelled, not counted as passes |
| Accelerator-linked LAPACK GE/PO | **PASS 16/16** CPU/CUDA x real/complex x dd/td/qd/mpfr; every CUDA run records getrs/potrs/gesv/posv entry traces (63 gesv and 102 posv successes per run) |
| Shared ABI | **PASS**, exactly 8 added symbols/backend, 0 removed, 0 newly undefined imports |
| Archive hygiene | **PASS 32 archives**, no duplicate strong globals |

The public 512-bit Cgetrs(C) fallback probe retains all 256 reference negative
zeros after the CPU binding fix (the old path retained none). Its complete
fallback oracle also covers driver A/pivots/info, not just X.

Reproduction names: `ctest -R cuda_solver_` covers the direct/fallback/copy
fixtures; MPFR precision tests are individually named
`mpfr_cuda_solver_{host,device}[_runtime]_<bits>`. Run the expected-failing
copy controls without concurrent GPU jobs from a separate CTest invocation.
Autotools uses `make -C mpblas/optimized/<backend>/cuda check`.

**UNVERIFIED:** other GPU architectures (sm_90 compiled, not executed),
full solver numerical coverage above the required six precisions (4096-bit
small-frame/stack paths were separately checked), and
performance crossovers at other precisions/unsampled sizes. No such result
or crossover is inferred from eligibility alone.
