# Resident CUDA inverses (factorization goal 09)

The dd/td/qd CUDA libraries expose real **and** complex `trtri`, `lauum`,
`potri`, and `getri`, with bool entry names `<Routine>_<backend>_cuda`.
Include `mpblas_<backend>_cuda.h` and link `libmplapack_<backend>_opt_cuda`.
The signatures are the LAPACK signatures, including GETRI's pivots/work/lwork.
Headers are generated by `misc/gen_accelerator_headers.py`.

The [cut-short gate retune](../../../benchmark/results/2026/x86_64-pc-linux-gnu-Ryzen-Threadripper-3970X-TeslaA100/gate-retune/README.md)
preserves completed Lower/nonunit inverse measurements but leaves every inverse
entry opt-in. qd large points are incomplete, Upper/UNIT performance unmeasured,
and MPFR inverse comparisons were not reached. Goal 11 adds opt-in MPFR
entries without changing those historical timing conclusions.

## Contract and default results

* `true`: the device computed the result, including a positive singular
  `info`. `false`: A, work, pivots and info are all untouched. Invalid flags,
  dimensions, pointers or pivots, n=0, GETRI workspace queries, disabled or
  below-threshold calls, memory/transfer/kernel errors reject publication.
* A stays on the device through every step: one matrix upload/download,
  O(n*nb) scratch for GETRI, O(1) device status otherwise. Only referenced
  triangles are uploaded/published; padding and unit-diagonal storage are
  preserved. Pivots are input-only. A non-unit zero diagonal returns the
  first singular index before any inverse arithmetic or A modification.
* Default uses the reference iMlaenv blocking, flags, full reductions and
  scalar representations, with BF operators and `-fmad=false` /
  `-ffp-contract=off`. No reduction axis is split. TRMM/TRSM distribute only
  independent columns/rows; GEMM distributes output elements. The current
  fast setting retains the same reference-order device arithmetic.
* Device leaves and their missing BLAS dependencies are generated from the
  **unchanged** FABLE sources by `misc/gen_inverse_device_reference.py`.
  Complex Level-3 arithmetic reuses `blas_dev`. Integer MOD is adapted to
  C++ remainder rather than a host-only fable intrinsic. No reference
  routine body is edited or independently maintained by hand.
* GETRI implements both reduced-workspace/unblocked and blocked schedules,
  including the reference workspace recommendation and final `work[0]`.
  Scratch is output-only: uninitialized host work is not read. Only slots
  written by the reference copy loops, plus work[0], are published; the
  remainder of the caller's workspace is preserved.
* Nonblocking kernels wait for default-stream pageable uploads. All kernels
  and transfers must complete successfully before **any** host publication.
  There is no CPU computation/fallback inside a bool entry point.

## Eligibility (read at every call)

`<P>` is `MPLAPACK_DD`, `MPLAPACK_TD`, or `MPLAPACK_QD`.

| Variable | Meaning |
|---|---|
| `<P>_LAPACK_CUDA=0` | disable resident inverse entry points |
| `<P>_LAPACK_CUDA_MIN=N` | common n override |
| `<P>_LAPACK_INVERSE_CUDA_MIN=N` | inverse-specific minimum, overrides common |
| `<P>_LAPACK_FAST=1` | currently the same device arithmetic |
| `<P>_CUDA_VERBOSE=1` | upload / inverse / download wall intervals |

The default minimum is **opt-in (LONG_MAX)** for all eight routines in each
backend. Set the common or inverse-specific minimum to 0 to force eligible
small cases. No unmeasured crossover is invented: the maintainer requested
implementation-stage checks only, deferring the benchmark/gate stage. Other
factor/solver defaults are unchanged. Verbose intervals include host packing
and publication, but not allocation/free, and are not calibrated kernel-only
timings.

## CPU fallback is the CPU library's implementation

Ordinary LAPACK symbols shadow the CPU/reference basenames. On rejection,
TRTRI/LAUUM use the shared dedicated CPU sources. POTRI/GETRI keep their
reference outer algorithms **on top of those same dedicated CPU sources**,
with optimized CPU BLAS throughout (`Rinverse_cpu_blas.h` extends
`Rfactor_cpu_blas.h` to TRMM and the leaf BLAS). This also avoids retrying
GPU dispatch from the outer fallback. There is no private serial GEMM or
reference-only triangular-inverse substitute, no environment override and
no process-wide OpenMP ICV change. Global `MPLAPACK_LAPACK_FAST` selects
CPU recursion as in the CPU-only library.

## Verification entry points

`<b>_cuda_inverse_{host,device}_test --quick` covers n=0/3/65/131, real and
complex, U/L, unit/nonunit, singular TRTRI/POTRI/GETRI, signed zeros, lda>n,
GETRI pivoting, queries, and 1/2/optimal workspace columns. Numerical n>0
calls must be accepted by the bool entry; unexpected rejection fails the
suite. Default compares complete A/work component representations. Fast
checks product/inverse residuals. n=0/query numerical wrapper cases use the
CPU's no-computation semantics; separate direct-entry rejection checks
require untouched A/work/pivots/info for these cases. Device tests exit 77
without a device; host emulation needs neither a GPU nor nvcc.

CMake registers full, quick, and fast-quick tests with SKIP_RETURN_CODE 77.
Autotools `make check` includes the host variant. Full numerical sweeps,
lin inverse/driver suites, sanitizer checks and crossover benchmarks are
**deferred**, not claimed from quick tests. Implementation-stage receipts:
[batch results](../../../benchmark/results/2026/x86_64-pc-linux-gnu-Ryzen-Threadripper-3970X-TeslaA100/factorization-batch-09-10/README.md).

Goal 11 adds the same eight MPFR entries using `Rinverse_schedule.h` (the
schedule extracted without arithmetic changes from the original BF engine).
Its MPFR-local adapters reuse the fixed/runtime factor arithmetic, launch
context, precision/arena mutex and full stack-memory preflight. See the
[MPFR inverse contract](../../../mpblas/optimized/mpfr/cuda/README.md#device-resident-inverses-goal-11)
for precision/exponent eligibility and focused tests. No MPFR inverse
performance crossover is claimed.
