# AGENTS.md — MPLAPACK repository guide for coding agents

## What this repository is

MPLAPACK: multiple-precision BLAS + LAPACK in C++. Backends: gmp, mpfr, qd,
dd, td, double, binary80, binary128. Two build systems in parallel: autotools
(configure.ac, Makefile.am tree, regenerated via ./gen_configure.sh) and
modern CMake (CMakeLists.txt + cmake/). Both must stay green.

`backends.txt` is the backend table (name, REAL/COMPLEX types, CMake default,
build traits).  CMake (cmake/MplapackBackendTable.cmake) and the fable header
generators (fable/gen_include_*.sh via misc/backends.sh) read it; do not add
backend name lists to those.  mpblas/optimized/<b>/Makefile.am,
mpblas/test/<b>/Makefile.am, mplapack/test/compare/<b>/Makefile.am and
benchmark/Makefile.<b>.am are generated by misc/gen_backend_makefiles.py from
misc/backend_makefiles/ (templates plus backends.conf); never edit them by
hand.  gen_configure.sh fails when they are stale.  configure.ac and the other
Makefile.am files still list backends by hand.  docs/adding-a-backend.md is the
recipe for adding a backend (misc/backend_sites.py <model> <new> lists the
sites still to handle, misc/backend_rename.py does the renaming copy); keep
it current when this changes.

## Hard rules

- Sources under `mpblas/reference/` and `mplapack/reference/` are
  FABLE-generated translations of Fortran LAPACK. NEVER edit routine bodies
  there. Fixes to numerics go through the fable pipeline, not hand edits.
- `include/mplapack_config.h` in the source tree may be a stale autotools
  artifact; the CMake build generates its own under the build dir and must
  keep winning via include order.
- dd backend requires -ffp-contract=off on every TU; removing it silently
  corrupts double-double arithmetic.
- Version numbers live in BOTH configure.ac and CMakeLists.txt; change both.
- libtool -version-info is ABI versioning, independent of package version.

## Accelerator entry points (naming rule)

Every routine an accelerator library computes has a public entry point that
calls the accelerator directly, named

    <Routine>_<backend>_<accelerator>      e.g. Rgemm_dd_cuda, Rgemm_qd_cuda,
                                                Rgemm_mpfr_cuda, Rgemm_binary128_opencl

- `<Routine>` is the MPLAPACK routine name (Rgemm, Cgemm, Rsyrk, ...),
  `<backend>` the backend name of backends.txt (dd, td, qd, mpfr, gmp,
  double, binary80, binary128), `<accelerator>` the suffix of the library
  that defines it, libmplapack_<backend>_opt_<accelerator> (cuda, opencl).
- Arguments: those of `<Routine>`, in the same order and with the same
  types (`const char *` flags, `mplapackint` sizes, the backend's scalar
  types).
- Result: `bool`.  true: the accelerator computed the result.  false: it did
  not (invalid arguments, quick-return cases, calls that are not eligible,
  device or runtime errors); every output is then left untouched.  The entry
  point never falls back to the CPU itself.
- It honours the same environment variables as the dispatcher (enabling,
  size threshold, algorithm and arithmetic selection, verbosity), which are
  documented next to it.
- Declared in `include/mpblas_<backend>_<accelerator>.h` (installed with that
  library; autotools: Makefile.am mplapack_include_HEADERS under the
  library's conditional, CMake installs include/*.h); defined in the
  accelerator library.  Programs call it with that header and link the
  library.
- The dispatcher `<Routine>` of the accelerator library (it shadows the
  optimized one, see the layered basename rule) calls the entry point and
  computes on the CPU when it returns false.
- Helpers (bridges, kernels, launchers) are not public: put them in a
  namespace or make them static, and never give them a name of this form.

Migration (not done yet): the dd/td/qd CUDA entry points are named
`<Routine>_gpu` (dd/cuda/Rgemm_bridge_cuda.cpp etc., common/blas_cuda/R*.cpp,
C*.cpp), the MPFR CUDA ones `<Routine>_mpfr_cuda` but with the dispatcher's
internal arguments (bool nota, notb, ...), and the binary128 OpenCL Rgemm
is `Rgemm_binary128_opencl_kernel` (void).  Bring them to this form, Rgemm
first, and update this paragraph.

## Ongoing work: unified library layout (branch topic/unified-libs)

The library taxonomy is being consolidated: one self-contained library per
flavor (libmplapack_<b>, libmplapack_<b>_opt, libmplapack_dd_opt_cuda,
libmplapack_binary128_opt_opencl), duplicate public symbols eliminated by a
layered basename-shadowing rule (accelerator > optimized > reference).
Normative spec: .agents/skills/unified-libs-goal/references/00-overview.md.
Execution units: references/01..05 in the same directory, driven by the
repo-local skill `unified-libs-goal` — one goal per session, in order
(invoke: "$unified-libs-goal 01"). Do not act on the goal files outside a
skill-driven session.

## Build quickstarts

autotools:
    ./gen_configure.sh
    ./configure --enable-dd --enable-double   # minimal fast config
    make -j$(nproc) && make check

CMake:
    cmake -B build -DMPLAPACK_ENABLE_GMP=OFF -DMPLAPACK_ENABLE_MPFR=OFF \
          -DMPLAPACK_ENABLE_QD=OFF -DMPLAPACK_ENABLE_BINARY128=OFF \
          -DMPLAPACK_BUILD_TESTS=ON
    cmake --build build -j && ctest --test-dir build

## Verification assets

- misc/check_unique_symbols.sh <lib...> — fails on duplicate global defined
  symbols inside one library. Run it on every archive you produce.
- Test suites live in mpblas/test and mplapack/test; they compare against
  reference results and are the ground truth for numerical correctness.
