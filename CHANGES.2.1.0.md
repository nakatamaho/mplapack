# MPLAPACK 2.1.0 Release Notes

## Highlights

### C++17 Now Required — Breaking Change ⚠️

MPLAPACK 2.1.0 requires C++17 or later.
Users building with older compilers must upgrade their toolchain.

### binary128 / binary80 Unified Naming — Breaking Change ⚠️

All library names, configure flags, header names, and type names for the
`_Float128` (128-bit) and `_Float64x` (80-bit extended) backends have been unified
under the `binary128` / `binary80` naming scheme. This is a breaking change for all
users of these backends.

| Item | 2.0.x | 2.1.0 |
|---|---|---|
| Configure flag | `--enable-_Float128` | `--enable-binary128` |
| Configure flag | `--enable-_Float64x` | `--enable-binary80` |
| Library | `libmplapack__Float128` | `libmplapack_binary128` |
| Library | `libmpblas__Float128` | `libmpblas_binary128` |
| Library | `libmplapack__Float64x` | `libmplapack_binary80` |
| Library | `libmpblas__Float64x` | `libmpblas_binary80` |
| Header | `mplapack__Float128.h` | `mplapack_binary128.h` |
| Header | `mplapack__Float64x.h` | `mplapack_binary80.h` |
| Type | `_Float128` / `__float128` | `mplapack_binary128_t` |
| Type | `_Float64x` / `long double` (ext.) | `mplapack_binary80_t` |

`mplapack_binary128_t` and `mplapack_binary80_t` are defined in `mplapack_config.h`
and resolve to the correct underlying type per platform and compiler, eliminating the
need for `#ifdef` guards in user code.

See [MIGRATION.md §2](MIGRATION.md) for full migration instructions.

### MPFR Exponent Range Auto-Adjusted with Precision — Breaking Change ⚠️

When `MPLAPACK_MPFR_PRECISION` is set, `emin`/`emax` are now automatically adjusted to
`±prec * 64` (clamped to platform limits). In 2.0.x the exponent range was fixed
regardless of precision, causing underflow/overflow at high precisions.
Setting `MPLAPACK_MPFR_EMIN`/`MPLAPACK_MPFR_EMAX` explicitly still takes precedence.

See [MIGRATION.md §1](MIGRATION.md) for details.

### Compiler/Toolchain Support Constraints ⚠️

| Compiler | binary128 | binary80 |
|---|---|---|
| GCC | ✅ Supported | ✅ (x86/x86\_64 only) |
| Intel oneAPI (icx/icpx) |  ✅ Supported | ✅ (x86/x86\_64 only) |
| Clang/LLVM | ❌ Not supported | ✅ Supported |

> **Clang users:** `binary128` is not supported. Use GCC for full precision support.

### Fable Standalone Component — Automated Fortran-to-C++ Conversion

`fable/` is now a top-level, standalone component providing automated Fortran-to-C++
conversion of LAPACK 3.9.1 sources via [Fable](https://cci.lbl.gov/fable/) and FEM
(Fortran Emulator, used only for test programs).

> **Note:** The Fable conversion pipeline is **not included in the release tarball**.
> It is available only via Git clone. Regenerating sources also requires expanding the
> bundled LAPACK 3.9.1 source under `external/lapack/` before running the scripts.

Permanent design decisions:
- **Library routines (BLAS/LAPACK):** Converted by Fable only. FEM is **not** used.
- **Test programs (EIG/LIN/MATGEN):** FEM is used for formatted I/O support.
- **152 patches** under `fable/3.9.1/` handle cases not automatable by Fable.
- A subset of public headers (`mpblas_gmp.h`, `mplapack_gmp.h`, and per-category/precision
  combinations for EIG/LIN/MATGEN) is auto-generated by shell scripts.
  Other headers such as `mplapack_utils_*.h` remain hand-maintained.

```sh
# Requires: git clone + external/lapack expanded
bash fable/go.sh          # library routines
bash fable/go_testing.sh  # test programs (EIG/LIN/MATGEN)
```

## Breaking Changes

- **C++17 now required.** GCC 7 or later is needed. Older compilers are no longer supported.
- **binary128/binary80 rename:** configure flags, library names, headers, and types all
  changed. All users of these backends must update. See [MIGRATION.md §2](MIGRATION.md).
- **MPFR emin/emax auto-adjustment:** behavior when `MPLAPACK_MPFR_PRECISION` is set has
  changed. Pin `MPLAPACK_MPFR_EMIN`/`EMAX` explicitly to preserve old behavior.
  See [MIGRATION.md §1](MIGRATION.md).
- **Intel oneAPI:** `binary128` and `binary80` are both broken with current icx/icpx.
  Intel oneAPI 2023 and earlier worked correctly but are no longer readily available.
  Switch to GCC. See https://github.com/nakatamaho/mplapack/issues/77.
- **Clang:** `binary128` is not supported.
- **DD/QD output precision reduced:** DD from 32→30 significant digits, QD from 64→61
  digits, to eliminate spurious last-digit mismatches across MPFR versions.
  See [MIGRATION.md §3](MIGRATION.md).

## Bug Fixes

### Eigenvalue / Eigensolver (EIG)

- **`Rdrvst2stg`: infinite loop and segfault fixed.**
  A Fable conversion bug caused three `goto statement_700` jumps in the `Rsyevr(V,V)`
  test section (tests 76–78) to branch backward into the `Rspev` section instead of
  advancing to the next `iuplo` iteration. The resulting infinite loop exhausted resources
  and caused a segfault. Fixed by introducing `statement_1720` as the correct forward
  jump target.
  Reproducer: `xeigtstR_mpfr < se2.in` with N=3, JTYPE=10, ISEED=(47829,4273,63548,61012).

- **GMP eigenvalue bisection: iteration-count cap extended to GMP.**
  GMP's effectively unbounded exponent range causes astronomically large `itmax`/`maxitr`
  values from the log-based formula. The existing 100,000-cap guard (previously MPFR-only)
  now also covers GMP. Affected: `Rlarrb`, `Rlarrd`, `Rlarrk`, `Rstebz`.

- **GMP test thresholds raised in `Rchkee`.**
  GMP has lower effective accuracy than MPFR/DD/QD in certain eigensolver code paths.
  Adjustments (GMP-specific only; MPFR is unaffected):
  - Non-symmetric block driver: 3.0× → 4.0×
  - Symmetric driver: 1.5× → 2.0×

### Numerics / Arithmetic

- **`mpcomplex` multiplication assignment operator fixed** (PR #74, contributor: pcbcos).
- **`binary128` complex print helper:** `n` variable reused correctly for `quadmath_snprintf`.
- **`binary128`/`binary80` I/O:** explicit `+` sign enforced in `strfrom`-based output paths.
- **`long`/`unsigned long` I/O overloads** fixed for ILP32/LLP64 platforms to prevent
  truncation on Windows and Debian i386.

### Known Issues

- **`lin/dd`: elevated failure count on AArch64 (ARM) — suspected GCC bug.**
  On Raspberry Pi 4 (Cortex-A72, AArch64, Ubuntu 24.04, GCC 13.3.0), the `lin/dd` test
  suite shows 226 failures (0.03%) vs. the expected ≤ 12 (0.00%) on amd64. All other
  backends and `eig/dd` on the same hardware are within the normal range. The root cause
  is under investigation and is suspected to be a GCC bug on AArch64 affecting
  double-double arithmetic.
  See: https://github.com/nakatamaho/mplapack/issues/76

### Portability / Platform

- **`binary80`: `M_PIl` replaced with portable hex-float literal.**
  `M_PIl` is a non-standard extension absent from musl libc (Alpine Linux). Replaced with
  `0xc.90fdaa22168c235p-2L`, portable across glibc, musl, macOS, and MinGW.

- **Fable `execinfo.h` conditional via `__has_include`.**
  Alpine Linux (musl) does not provide `<execinfo.h>`. Backtrace support is now disabled
  automatically when the header is absent, without requiring `libexecinfo`.

- **`std::once_flag`/`call_once` replaced with `std::atomic<bool>`** for MinGW win32
  thread model compatibility.

- **FPU precision mode** set before test code runs in QD/DD BLAS test binaries.

- **Alpine Docker image:** GNU sed added explicitly (BusyBox sed lacks the `e` command).

### Build System

- **`$(top_builddir)` → `$(top_srcdir)`** for `fix_dylib_macOS.sh` and
  `cpu_os_detection.sh` across all test `Makefile.am` files (VPATH build fix).

- **Jobserver propagation:** `+` prefix added to all `${MAKE}` invocations in external
  subdirs (gmp, mpfr, mpc, qd, lapack, openblas). Removes spurious `-j1` fallback warning.
  Explicit `MAKEFLAGS = -j 1` removed.

- **`distclean`/`distcheck` failures in external subdirs fixed.** Bare `clean:`/`distclean:`
  targets replaced with `clean-local:`/`distclean-local:` automake hooks in all external
  subdirectories (dlfcn-win32, gmp, lapack, mpc, mpfr, openblas, qd).

- **Wildcards in `EXTRA_DIST` replaced with explicit file lists.**

- **`qd_extra_cxxflags` propagation fixed:** missing `AC_SUBST` in `configure.ac` caused
  the flags to never be substituted into any Makefile.

- **`gen_include_mplapack.sh`:** additional internal symbols filtered from public header
  aggregation.

- **`quadmath` flag substitution spacing** fixed in generated example Makefiles.

## New Features and Enhancements

### Fable & Code Generation

- `fable/` promoted to top-level standalone component (available via Git clone only;
  not included in the release tarball).
- A subset of public headers auto-generated by shell scripts: `mpblas_gmp.h`,
  `mplapack_gmp.h`, and per-category/precision combinations for EIG/LIN/MATGEN.
  `mplapack_utils_*.h` and other headers remain hand-maintained.
- Conversion covers BLAS/LAPACK library routines and test programs (EIG/LIN/MATGEN).
- 152 targeted patches under `fable/3.9.1/` for Fortran constructs not handled by Fable.

### Platform & Architecture

- **Debian i386 (ILP32) support:** `mplapackint` unified with platform `long` to match
  the GMP/MPFR C API (`long`-only); ILP32/LLP64 I/O overloads added to prevent truncation.
  `Dockerfile_debian12_386_devel` added.
- **CUDA 13.1.1** branch build jobs added for Ubuntu 22.04/24.04 (amd64).
- **Rocky Linux 8/9** and **Alpine 3.19** (amd64, arm64) added to branch build matrix.
- **MinGW-w64** cross-compile jobs added (Ubuntu 22.04/24.04 hosts).
- **Debian 12** including `linux/mips64le` added alongside Debian 13.

### Test Infrastructure

- `summarize_mplapack_tests.py` added; executed automatically after `make check`.
- `cpu_os_detection.sh` for deterministic CI platform identifiers.
- `Rlaruv` test enhanced with Welford-based statistical sanity checks
  (mean, variance, min, max, chi-squared). Deterministic mode made platform-independent.
- `Rlamch` and `Rlaruv` reference outputs added/renamed per backend.
- Test outputs routed into `CPU-OS-Compiler` subdirectory for disambiguation.
- EIG/LIN backend checks parallelized with jobserver-safe recursive make.

### Build Scripts

- Tiered build/test scripts added and consolidated (see Platform Support Tiers below).
- macOS tier1: WORKDIR fixed to `$HOME/tmp/mplapack` for improved ccache hit rate,
  with atomic lock and stale-lock detection.
- `AX_MPLAPACK_CC_TAG` macro added for robust compiler tag identification in CI.
- `MPLAPACK_BINARY128_MODE_*` and `MPLAPACK_BINARY80_MODE_*` AM_CONDITIONALs added.
- `iMlaver` generation and VPATH-safe external extraction added to `configure.ac`.

### Benchmark

- Benchmark subtree flattened: `mpblas/` and `mplapack/` subdirs merged into `benchmark/`.
- `go.*.sh` generated from `go.*.sh.in` templates with two-phase substitution.
- Warmup passes, statistical timing, CSV output, and dynamic symbol resolver support added.
